# Destiny Matrix Notes And Interpretation Catalog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:executing-plans` and `superpowers:test-driven-development`.
> Execute locally without subagents for this repository task.

**Goal:** Add astrologer-private notes bound to saved Matrix checksums and a
versioned RU/EN deterministic interpretation catalog, without adding client
visibility, publication, sessions, messaging, AI, report or PDF behavior.

**Architecture:** Extend the Matrix bounded context with a note persistence port
and pure catalog resolver. Add one `matrix_notes` table and Drizzle adapter under
the Matrix DB boundary. Expose authenticated Matrix note CRUD plus a read-only
catalog lookup from a focused Nest controller/service. Every note belongs to an
owned saved Matrix calculation and carries the result checksum that was current
when the note was created or edited; stale state is derived on read.

**Tech Stack:** TypeScript 6, Zod, NestJS 11, Drizzle ORM/PostgreSQL, Vitest,
pnpm/turbo.

## Product And Safety Constraints

- Notes are private to the astrologer. There is no visibility toggle and no
  client-facing route.
- Notes exist only for persisted `module = matrix` calculations; preview has no
  note identity.
- Create/update require `expectedResultChecksum` equal to the current saved
  result. Recalculation preserves notes and makes older note revisions visibly
  stale.
- Delete may remove current or stale notes and remains owner-scoped.
- Note text is trimmed, 1–10,000 characters, plain text only.
- Catalog revision is `1`, locales are `ru | en`, arcana are `1..22`, and
  contexts are `portrait | talent | karmic | relationship | money | lineage |
purpose | energy | compatibility | forecast`.
- Catalog content is authored code, not scraped competitor text and not runtime
  AI/translation output. Base arcana language and context-specific guidance are
  composed from separate reviewed RU and EN source maps.
- There is no DB reset in this plan without separate explicit authority. The
  checked-in baseline migration is regenerated and schema-tested; local reset
  remains a destructive follow-up operation.
